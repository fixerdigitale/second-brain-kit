# From a book to a skill

**The problem.** I read method books (sales, design, management) and then don't apply them. Rereading them when they're needed never happens.

**How I solved it.** I use book-to-skill: it takes a PDF, EPUB, DOCX or text and extracts frameworks, principles, techniques and mistakes to avoid. The result is a skill Claude uses while working.

**Why this way.** A book turned into a skill becomes a checklist that enters real work, not a note that stays in the vault. It's the same principle as several design skills I use: refactoring-ui, for example, comes from a book.

**When you need it.** Books or technical manuals you want to apply often, long internal procedures to turn into rules.

**When you DON'T need it.** For books read once for pleasure. And mind the copyright: the skill that comes out is for your own use, not for republishing.

**How to get it.** Third-party skill, from the source: https://github.com/virgiliojr94/book-to-skill (it goes in `~/.claude/skills/book-to-skill/`; it has Python scripts).
